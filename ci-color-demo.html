PR Companion: Confidence Interval Saturation Fading for the Matchup Matrix

This document explains the motivation, statistical reasoning, and visual effect of a small change to src/lib/utils/format.ts and src/lib/components/MatchupMatrix.svelte.

1. The problem

The matchup matrix already computes and displays a 95% confidence interval — but only in the hover tooltip, which is invisible unless you know to look for it. A non-technical player loading the matrix sees colored cells and reads them as definitive results.

Consider these real cells from the Modern matrix:

All three cells show roughly 60% and look equally authoritative. The tooltip is the only signal that the first result (n=8) has a CI spanning 33%–84% — strongly consistent with a coin flip — while the last (n=150) has a CI of 52%–68%, genuinely above 50%.

2. The existing color system has unused capacity

winrateColor() in format.ts maps win rate to fixed-saturation pastels (red / neutral / green). Saturation is never varied — a cell that is deep green at 80% win rate looks equally vivid whether it is based on 5 matches or 500. This is an unused visual dimension that can encode uncertainty without adding any new UI elements.

3. The solution: blend toward neutral proportionally to CI width

We pass the CI width (upper − lower bound, a value between 0 and 1) into winrateColor() as an optional second parameter. The color is then linearly interpolated toward neutral gray rgb(245,245,245) by a fade factor: 

// New optional parameter, default 0 = no fading (backwards-compatible)
export function winrateColor(wr: number, ciWidth = 0): string {
  // ... existing hue calculation unchanged ...

  if (ciWidth > 0) {
    // Multiplier 1.0: fade reaches max at CI width = 0.6
    // Max fade 0.6: even n=5 cells retain 40% of their hue
    const fade = Math.min(ciWidth, 0.6);
    r = Math.round(r * (1 - fade) + 245 * fade);
    g = Math.round(g * (1 - fade) + 245 * fade);
    b = Math.round(b * (1 - fade) + 245 * fade);
  }
  return `rgb(${r},${g},${b})`;
}

The call sites in MatchupMatrix.svelte compute the Wilson CI width and pass it through:

// Matrix cells
{@const [ciLo, ciHi] = wilsonCI(cell.wins, cell.total)}
// ...
style={`background-color: ${winrateColor(cell.winrate, ciHi - ciLo)}`}

// Overall column
const [lo, hi] = wilsonCI(s.wins, s.totalMatches);
return `background-color: ${winrateColor(s.overallWinrate, hi - lo)}`;

Why Wilson CI, not the Bayesian credible interval already in statistics.ts?

The component already had a local wilsonCI() function used for the tooltip. Reusing it keeps the tooltip and the cell color consistent (same CI method, same numbers). The two methods diverge by at most ~2–3 percentage points in typical cases, so the choice has no meaningful effect on the visual result.

Why these tuning values (multiplier 1.0, max fade 0.6)?

The fade formula is min(ciWidth × multiplier, maxFade). The parameters were chosen to satisfy two goals:

  • Cells with very small n (≤10) should look noticeably washed out, but not unreadably gray.
  • Cells with large n (≥200) should look nearly full-color.

6. What this change does NOT do

  • Does not remove or change the tooltip — CI numbers are still shown on hover.
  • Does not change any data, win rate calculations, or the CI method.
  • Does not affect cells with no matches (still shown as "—").
  • Is backwards-compatible: winrateColor(wr) with no second argument behaves identically to before.

7. Code diff summary

src/lib/utils/format.ts — winrateColor() refactored to compute RGB as variables (instead of early returns) so the optional fade blend can be applied before returning. New optional parameter ciWidth = 0.

src/lib/components/MatchupMatrix.svelte — two call sites updated:

  • Matrix cells: {@const [ciLo, ciHi] = wilsonCI(cell.wins, cell.total)} added; ciHi - ciLo passed to winrateColor.
  • Overall column (overallStyle()): same pattern using s.wins / s.totalMatches.
